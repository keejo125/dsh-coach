## 二、P1 —— 自洽性与可辨识性（影响"一眼读懂"）

### 1. Skill 调用卡：头部计数与「最近调用」列表对不上
**证据**：`v0917-token-agents.png`、`v0917-subagent-cards.png`。卡头写「调用 1 次 · 失败 1」，右侧又写「workflow 调用 1 失败 1」，但下方「最近调用」列了 **3 行** R5 workflow（首行无徽章、后两行各带红「失败」）。
**问题**：1 vs 3 无法自洽——要么"调用 1 次"是去重口径而列表是工具级调用，要么列表多渲染；两种可能 UI 都未说明。同一张卡上 1 与 3 并列，用户会判读数错误（与 `44a1815` 刚修的产物口径自洽是同类病，Skill 卡遗漏）。
**方法论依据**：design-methodology §7「组件状态/口径自洽」、§3「不靠数字单独传义需有对照」。
**修复建议**：统一口径——若"调用 1 次"指 1 次唯一 Skill 调用、列表是其重试/子调用，列表副标注「（同一调用的 3 次工具级执行，失败 2）」；或直接把头部改为「调用 3 次 · 失败 2」与列表对齐。
**优先级**：P1

### 2. 子智能体全部同名 "standard"，无法一眼区分
**证据**：`v0917-subagent-cards.png`、`v0917-drawer-agent.png`。9 个可读子智能体徽标全为 `standard`，抽屉标题也是「子智能体 · standard」。区分只能靠截断任务描述的前十几个中文字。
**问题**：README 推导链 `descriptor.label → agentPreset → id前8位` 在本场全部落到 `agentPreset="standard"`，于是 9 张卡在「徽标」这一列完全相同，格式塔"相似性"把它们误判为重复卡片；用户想点"那个写 HTML 的子代理"只能逐行读任务首词。
**方法论依据**：design-methodology §2 相似性（不同实例应给不同视觉锚点）、§1 视觉层次。
**修复建议**：徽标在 label 缺失时回退到「standard · `<id前6位>`」或任务首词（如「HTML 子代理」），抽屉标题同步带上区分后缀；至少让两张卡的徽标列肉眼可辨。
**优先级**：P1

### 3. 「21 交互轮次」与「24 轮」双口径同屏无注释
**证据**：`v0917-top-overview.png`（统计 21 / Token 卡「查看全部 24 轮」）、`v0917-drawer-token.png`（抽屉「全量轮次·24 轮」，其中 R13/R14/R16 标注「（工具处理轮）」）、时间线卡「共 21 轮」、状态栏「24 轮」。
**问题**：21 = 用户发起轮次，24 = 含 3 个工具处理轮的全量轮次，这本身合理，但页面同屏出现 21 与 24 两个总数，没有任何一处说明差值来源，评审者第一眼即判为"数对不上"。
**方法论依据**：design-methodology §7 一致性（同一概念多处出现须同口径或注明差异）。
**修复建议**：时间线卡副标由「共 21 轮 · 点击展开复盘明细」改为「共 21 个用户轮（含 3 个工具处理轮，全量 24）」；或在统计「21 交互轮次」下方加 12px 灰字注解「全量 24 轮」。一处即可，不用全部改。
**优先级**：P1

## 三、P2 —— 细节 / 一致性 / 可读性

### 4. 雷达图六个轴标签中英混排冗余
**证据**：`v0917-top-overview.png`。每轴都是「中文 + 英文 pinyin + 数字」三行：完成度 completion 90 / 效率 efficiency 97 / 上下文 context 80 / 委派 delegation 40 / 产物 artifact 75 / 恢复力 recovery 0。
**问题**：一个雷达上叠 12 行小字（6 中文 + 6 英文），英文是占位符式机翻标签，对中文用户无增量信息，反而把雷达多边形衬得很乱。
**方法论依据**：design-methodology §4 中英文混排、§8 留白降噪。
**修复建议**：轴上只留「中文 + 数字」（完成度 90 …），英文移到 hover/抽屉的指标说明里；或雷达旁放一个紧凑图例。
**优先级**：P2

### 5. 时间线同类徽章实心/描边不统一
**证据**：时间线截图（R5「引用 1」描边灰徽章 vs 同行「产物 3」绿底实心；R7「产物 4」绿底；R12「干预」「纠错」描边琥珀/红）。
**问题**：同为"计数徽章"，引用走描边、产物走绿底实心，视觉权重不一致——用户会误以为实心=重要、描边=次要，其实它们是平级的标签。
**方法论依据**：design-methodology §2 相似性（同功能元素同款式）、§7 一致性。
**修复建议**：统一徽章基底——要么全部描边（语义色描边），要么全部按语义色浅底实心；用颜色区分"引用/产物/干预/纠错"四类，而不是用实心/描边再叠一层语义。
**优先级**：P2

### 6. 引用分析文件名截断后两行肉眼同名
**证据**：`v0917-refs-artifacts.png`。`todo-app/src/hooks/us…` 出现两行（实为两个不同 hook 文件），其余 `todo-app/research-rep…`、`todo-app/src/types/to…`、`todo-app/tests/unit/u…` 均只截中段。只有 timer-app/index.html 完整显示。
**问题**：截断把路径中段切掉、保留前缀，导致不同文件前缀相同部分完全一样，两行在列表里长得像双胞胎，必须 hover 才能区分。
**方法论依据**：design-methodology §4 每行长度与可读性。
**修复建议**：截断策略改为"保留尾部区分段"——长路径用 `…/hooks/useXxx.ts` 形式（尾部省略前缀而非头部），或文件名列用等宽 + 右侧固定宽度、超长时尾部省略。
**优先级**：P2

### 7. 抽屉打开时残留黑色 tooltip 浮于抽屉头部
**证据**：`v0917-drawer-r5.png`、`v0917-drawer-token.png`。R5 抽屉顶部悬浮一个黑色气泡「用workflow的方式完成一个定时器的网页开发」，盖住抽屉头区域，关闭抽屉才消失。
**问题**：这是点开轮次行时行上 hover tooltip 未随抽屉打开而销毁，层级错乱地浮在 dialog 之上，遮挡抽屉标题区。
**方法论依据**：design-methodology §2 图底关系（弹层用遮罩拉开层级）、§7 组件状态完整（tooltip 应随触发状态退出）。
**修复建议**：抽屉打开/路由切换时清空悬停态与 tooltip；或 tooltip 的 z-index 低于 dialog、且 pointerenter 移出即销毁。
**优先级**：P2

### 8. 卡头「总量 88,956 · 输入 3,508,961」量级并列易误读
**证据**：`v0917-top-overview.png`。输入是总量的约 39 倍（累计提示词 vs 净增量），同框并列。
**问题**：前者是本场 token 净额、后者是按事件文本量累计的提示词总量，口径不同但没在卡头标"累计"，普通用户第一反应是"输入比总量还多？"。
**方法论依据**：design-methodology §7 数据可信。
**修复建议**：卡头改「总量 88,956 · 累计输入 3,508,961 · 输出 102,529 · 缓存 87,552」，或在「按事件文本量估算」hint 里点明输入为累计值。
**优先级**：P2

### 9. 建议落点徽章暴露完整绝对路径（含用户名）
**证据**：`v0917-suggestions.png`。「工作区 · /Users/zhengk/GitProjects/agent-docs/projects/harness/test/AGENTS.md · 已存在」整条绝对路径塞进一枚徽章，长且拥挤。
**问题**：徽章本应是短标签，塞进含用户名的绝对路径后换行/视觉负担重，也无必要暴露 home 目录。
**方法论依据**：design-methodology §4 每行长度、§7 一致性（徽章应短）。
**修复建议**：徽章只放「工作区 · AGENTS.md · 已存在」，完整相对/绝对路径进 tooltip 或折叠区。
**优先级**：P2

### 10. 子智能体"全零"卡信息密度过低
**证据**：`v0917-subagent-cards.png`。多张卡「读 0 文件 · 工具 0 次 · 有最终答复 · 产物 0」，三指标全 0，卡面只剩徽标 + 截断任务，与"读 3 文件·工具 7 次"的卡并排显得像占位卡。
**问题**：全 0 卡既无数据看点又占位，9 张里有一半是这种空卡，列表信噪比低。
**方法论依据**：design-methodology §8 留白与降噪、§1 层次。
**修复建议**：全零卡合并为一行折叠「其余 N 个子代理无工具/文件调用」，或给这类卡补一句最终答复首行预览（≤40 字）让卡面有内容。
**优先级**：P2

## 四、未实机确认、建议人工补测的两项

- **prefers-reduced-motion**：抽屉滑入 / chevron 旋转在自动化截图中无法校验动效时长与降级。建议在系统开启"减少动态效果"后复看抽屉开合并 hover，确认动效退化为即时切换（design-methodology §9、WCAG SC 2.3.3）。
- **深色对比度定量**：截图目视正文/边框对比度大致达标（抽屉内文件代码、统计数字清晰），但「按事件文本量估算」「依据：R12…」等 12px 灰字建议用取色器复核是否 ≥4.5:1（正文），图形/进度条边框 ≥3:1（SC 1.4.3 / 1.4.11）。
