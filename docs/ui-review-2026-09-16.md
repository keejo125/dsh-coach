> 评审日期：2026-09-16 ｜ 方法基线：ui-design-methodology（美感与设计方法论 + accessibility-wcag）
> 评审对象：复盘 Tab 实机全屏（1280×960 / 1160×788）逐模块截图核验
> 风格定调建议：**专业克制 · 数据质感**（深色仪表盘系）——数字是主角，一切设计服务于"一眼读懂这场会话好不好、哪里绕了路"。

## 二、P0 —— 清爽无空白（先修这批）

### 1. 中部两列失衡：Skill 卡大片空白
**证据**：右列 Skill 卡仅一行「workflow 调用1 失败1」，卡下至产物清单顶部约 **280px 空白**；左列子智能体卡（max-height 260 内部滚动）内容排满。两列 grid 行高被拉伸对齐导致。
**修复**（选一）：
- 两列改为 `align-items: start` + 各自行高，不强制等高；
- Skill 卡补内容：最近调用时序（时间线子集）、空态说明「本次无更多 Skill 调用」；
- 或将 Skill 卡并入产物清单上方成「调用-产物」组合卡。

### 2. 左列卡间空隙叠加
**证据**：子智能体卡底（约 y378）→ 引用分析卡顶（y440）约 60px，高于全站卡间距。
**修复**：统一卡间距 16px（8px grid 的 2 档），卡内 padding 统一 16px；确认 max-height 滚动容器底部不留多余 padding。

### 3. 本场统计数字未等宽对齐
**证据**：`88956`（5 位）与同列 `8`/`24` 右缘不对齐；`88956` 视觉溢出格子。
**修复**：统计数字全局 `font-variant-numeric: tabular-nums`；长数字（Token）用 K/M 缩写（`88.9K`）与单位统一显示；格子内数字统一右对齐或居中对齐。

### 4. Token 分布「输入构成」一行三栏挤爆
**证据**：「●系统提示词 15,235 ●用户提示词 589 ●工具调用 193,295」挤在单行小字，与「按事件文本量估算」提示同区混排。
**修复**：四类构成改为 **4 列数字块**（复用上下文构成卡的数字块样式）；「按事件文本量估算」降为右上角次要 hint（12px、低对比灰）。

### 5. Token 分布 R 行进度条对齐/视觉弱
**证据**：11 个 bar 存在但左缘不齐、无分色，肉眼几乎不可见（此前反馈过）。
**修复**：进度条统一容器宽度（文案列之后固定起位）、左对齐；按 input/cache/output 分色（同色板）；行高统一 40px；数字列等宽右对齐。可选：hover 显示「input/cache/output 拆分」。

## 三、P1 —— 一目了然 & 数据可信

### 6. 产物清单数字口径矛盾
**证据**：「共24个文件·新建23·更新3·迭代×3」→ 23+3=26 ≠ 24，可信度受损。
**修复**：统一口径并在副标题注明（如「共 24 · 新建 21 · 更新 3（含迭代 ×3）」），或改「新建 23 · 更新 3（去重后 24）」。

### 7. 引用分析两表信息重复、Top 语义弱
**证据**：参考共 8 文件，「高频引用 Top」列全部 8 条；「未使用引用」又列其中 7 条同一批文件。
**修复**：高频 Top 只列 **前 3~5** 条并带使用次数 bar；「未使用」改为与「已用」对比视图（或一张总表：文件名 + 查看次数 + 已用/未用徽章），避免两遍同样的文件名。

### 8. 上下文构成两行数字规格不一致
**证据**：第一行 21/3/11/0 数字大且居中；第二行「最终段 1 / 过程段 74」数字更小、位置偏下。
**修复**：数字块全站同规格（同字号、同 8px padding、同对齐）；两行都作为可下钻数字块。

### 9. 语义色未系统化
**证据**：失败 6、Skill 失败 1、「纠错/干预」标签色彩未统一（当前主要靠文字）。
**修复**：建语义色 token：失败=红、纠错/干预=琥珀、产物=青、引用=蓝、新建=绿、更新=琥珀；状态同色相 ±4~8% 做 hover/active。**不靠颜色单独传义**（标签文字保留）。

### 10. 建议区条目信息密度不均
**证据**：5 条×4 行（类型+标题+内容+依据）紧凑堆叠；「用户全局/工作区」落点行字号偏小。
**修复**：条目卡片化——类型徽章（规则/知识/偏好）+ 标题行（semibold）+ 内容 + 依据小字一行；落点用徽章「将新建 / 已存在」而非长路径文本。

## 四、P2 —— 细节 / 一致性 / 无障碍

### 11. 建议区标题层级
「复盘建议 共 5 条 ›」与副标题同层级 → 标题 16px semibold + 计数徽章（圆角小标签），副标题 12px 次要灰。

### 12. 抽屉标题层级
「交互详情·R12」字号与正文差距小 → 抽屉头 18px semibold，副信息（轮次/时间）12px 次要灰；内容区按「对话 → 参考 → 产物 → 过程」分区标题化。

### 13. 时间线行标签拥挤
R12 行 5 个标签（追问/干预/纠错/引用7/产物3）+ 箭头 → 窄屏会溢出。限制最多 3 个标签 + 「+N」。

### 14. 产物树「新建」标签×23
每行重复 → 建议仅「更新/迭代」行显示徽章，新建行用颜色/图标弱标记，或首次出现目录级标注。

### 15. 无障碍（WCAG 2.2 AA）
- 字号：辅助文案（「按事件文本量估算」「依据：R12…」）不得 < 12px，正文 ≥14px；核对深色下正文对比度 ≥4.5:1、图形/边框 ≥3:1；
- 焦点：所有可点元素（数字块/时间线行/树节点/标签）补 `focus-visible` 环（≥3:1）；
- 语义：抽屉 `role="dialog" aria-modal="true"` + 关闭后焦点回触发元素；时间线用 `<ol>`；数字按钮带 `aria-label`；
- 触控：数字块/行高保持 ≥44px（当前约 45px，OK）；
- 动效：抽屉滑入 300ms ease-out、chevron 150~200ms，尊重 `prefers-reduced-motion`。

### 16. 数字可读性
全站统计数字 `tabular-nums`；长数字（3,508,961）可缩写（3.5M）并保留精确值于 tooltip/抽屉。

## 五、建议落地顺序（与你的目标对齐）

1. **P0 五连**（空白/对齐/密度/进度条）→ 一次改完重验全屏——直接解决"清爽、无大片空白"；
2. **P1 五连**（口径/冗余/规格/语义色/条目卡片）→ 解决"重要信息一目了然、数据可信"；
3. **P2 打磨**（抽屉/标签/无障碍）→ 随发布前质检一起过。

> 说明：本轮为评审建议，未改动代码。确认优先级后可按批次开工，每批仍走 328 测试 + bundle + 全屏实测验证链。
