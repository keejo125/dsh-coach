## 三、P1 —— 色义自洽与交互一致性（影响"一眼读懂"与"点了会怎样"）

### 1. 图例「委派指令」色点无填充，色义断链
**证据**：`v0917b-token-card.png`。图例四项中「用户提示」「工具调用」「上下文注入」均有 8px 实心色点，唯「委派指令」位置是一枚透明空格；而同项在「字符量」条形里是**红色**（`rgb(236,19,19)`）。
**根因（已定位到代码）**：`CoachView.tsx:1309` 用 `css[\`profileDot_${part.key}\`]` 取色点类；parts 的 key 含 `delegation`，而 `CoachView.module.css:1031-1034` 只定义了 `.profileDot_system/_user/_tools/_plugin`，**缺 `.profileDot_delegation`**，于是该元素类名落到字面量 `undefined`（实测 `class="…profileDot undefined"`），计算 `background-color: rgba(0,0,0,0)`。
**影响**：图例是读懂上下两条双色条形的唯一钥匙，钥匙缺一格 → 用户无法把红段映射回"委派指令"。
**修复**：补 `.profileDot_delegation`，与条形同色。
**优先级**：P1

### 2. 「委派指令」复用 `error` 语义色，与「失败/纠错」同色
**证据**：`.profileSeg_delegation { background: var(--dsw-alias-state-error-primary) }`（`CoachView.module.css:999`）；时间线「纠错」徽章前景亦为 `rgb(236,19,19)`，「失败」徽章同为 `rgb(236,19,19)`。
**影响**：同一套色板里，红色同时表示"错误状态"和"委派指令"这一中性类别，两项语义互相污染——条形里那截红既可能被读成"这里出错了"，也会削弱「纠错/失败」的警示力。同类问题在 amber 上重复一次：`工具调用 = --state-warn-primary`，而「干预/未用」也用 amber。
**修复建议**：类别色与状态色分家。五类输入构成走一组中性偏冷的功能色（如墨蓝/青/灰阶），语义色（红/琥珀/绿）只保留给状态徽章；或保留现有色相但把类别色降饱和到 60%，并在图例加 1 行说明。
**方法论依据**：design-methodology §7 语义色系统化「不靠颜色单独传义、状态色不与类别色混用」。
**优先级**：P1

### 3. 图例四项同貌不同行为：「工具调用」点击后不打开抽屉，而是把整页滚走
**证据**：四个图例按钮外观、文案、`title` 完全一致（同为 `button.profileLegendItem`、同为 `title="点击查看明细"`）。实测：
- 点「用户提示」→ 打开抽屉「用户输入」（21 条列表）✅
- 点「委派指令」→ 打开抽屉「委派指令」✅
- 点「上下文注入」→ 打开抽屉「上下文注入」✅
- **点「工具调用」→ 无抽屉，页面整体滚动到页尾「交互时间线」卡**（源码 `CoachView.tsx:486` `case 'tools': scrollToCard('coach-timeline-card')`）

**影响**：同样的"点击查看明细"承诺给出两种结果；点「工具调用」后 Token 卡被滚出视口，用户丢失原位置，也没有得到"工具调用明细"（236 次调用的清单），只看到一个不相关的卡片。
**修复建议**：统一为打开「工具调用明细」抽屉；若确实要引导到时间线，则把该按钮换一种显著不同的样式与文案（如「在时间线中查看 ›」），并把其余三项也标成「点击查看明细」的动词短语，避免同貌异行。
**方法论依据**：design-methodology §2 相似性（同貌必同行为）、§7 组件状态完整。
**优先级**：P1

## 四、P2 —— 层级、键盘、可读性

### 4. 抽屉内首屏最重的是 12px 深色用户气泡，层次倒挂；并纠正上一轮 #7 的误判
**证据**：`v0917b-drawer-round.png`。抽屉头部「交互详情 · R7」下方紧贴一枚近黑（`rgb(15,17,21)`）右对齐气泡「实际中怎么使用？」，实测字号**仅 12px**（正文 16px，标题 16px），几何 `x=1136, y=66, 118×34`，位于 520px 宽抽屉的右上角。
**结论修正**：上一轮 #7 将同一现象判为"点开轮次行时 hover tooltip 未销毁、浮于抽屉之上"。实测该元素是**抽屉自己的用户消息气泡**（`div.bhhTdW_chatUser`，父级 `bhhTdW_chatBlock`，随抽屉挂载/卸载），并非残留 tooltip。因此按"清空悬停态/tooltip"的思路改不生效——确实现在仍在。
**真正的问题**：整屏最重的色块给了最小的字（12px），且紧贴标题行，读起来像浮层遮挡；同时它与抽屉标题争夺主视觉焦点（标题 16px 黑字 vs 气泡纯黑底）。
**修复建议**：气泡改用浅底 + 深字的引用样式（或左侧细线引注），字号提到 13–14px；与标题行留出 12px 间距。真实存在的那类"悬停提示残留"已随 `title` 文案改为短提示而大幅减轻，可在实机再复核一次（无头截图不含系统级原生提示）。
**优先级**：P2

### 5. 键盘焦点管理三处缺口
**证据**（键盘路径实测）：
- 聚焦时间线 R7 行 → 按 `Enter` → 抽屉打开，但 `document.activeElement` 仍停在触发行 `button.roundRow`，**焦点未移入 dialog**；
- 在抽屉打开态按 `Esc` → **抽屉不关闭**（`dialog` 仍在）；
- 关闭抽屉后 `document.activeElement` 落到 `BODY`，**未回到触发的行**。

**影响**：`aria-modal="true"` 的对话框按 APG 约定应"打开时移入焦点、Esc 可关、关闭后焦点归位"；当前三条都不满足，键盘/读屏用户打开抽屉后会失去位置感，且只能用鼠标点右上角 ✕ 退出。
**修复建议**：打开时 focus 到抽屉容器或第一个可聚焦元素；监听 `Escape`；关闭时 focus 回 `trigger` 元素（保留引用）。
**优先级**：P2

### 6. 兜底焦点环规则挂在未使用的类上，实际用的是浏览器默认 1px 环；且 102 个 Tab 位无方向键导航
**证据**：
- `CoachView.module.css:1281` 定义了 `.grid :focus-visible { outline: 2px solid var(--dsw-alias-brand-primary) }`，但全项目 TSX 只用了 `css.grid2`，**`.grid` 从未被使用**（实测页面仅有 `bhhTdW_grid2`）。逐级上溯确认：焦点元素无 `.grid` 祖先 → 复盘页所有控件的键盘焦点环回落为浏览器默认 `outline: auto 1px`。
- 复盘页可聚焦控件合计 **102 个**：柱图 24 柱 + 时间线 21 行 + 产物树 23 行 + 本场统计 12 项 + 其余。实测连续 `Tab` 需 12 次才能穿过「本场统计」、24 次穿过柱图。
**修复建议**：焦点环规则改挂到实际根容器（或直接 `:focus-visible` 全局）；柱图/时间线/产物树改为 roving tabindex + 方向键（各留 1 个 Tab 位），`Tab` 位可从 102 降到 ~30。
**优先级**：P2

### 7. 徽章前景色策略不统一，10 个状态徽章对比度不达 WCAG AA
**证据**（按 alpha 逐层合成白底后实测对比度，均为 11px 小字）：

| 徽章 | 前景/底 | 对比度 | 判定 |
|---|---|---|---|
| 引用 1 / 引用 7 | 深字 on 蓝 12% 底 | **16.44** | ✅ |
| 更新 | 10px | 4.68 | ✅ |
| 追问 | 白字 on 琥珀实心 | **2.15** | ❌ |
| 规则 | 琥珀字 | **2.15** | ❌ |
| 知识 | 绿字 | **2.28** | ❌ |
| 新建 | 10px 灰字 | 2.62 | ❌ |
| 数据不可读 | 11px | 3.51 | ❌ |
| 失败 / 纠错 | 红字 | 3.87 | ❌ |
| 未用 / 干预 | 琥珀字 | **1.81** | ❌ |
| 产物 1/3/4 | 绿字 | **1.94** | ❌ |

**问题**：「引用」系列把文字压成深色、只让底色带色相（16.4:1 达标），其余徽章直接拿语义色当文字色（1.8–3.9:1）。同一排徽章两套做法，既不一致也不达标。
**修复建议**：统一采用「深字 + 8–14% 语义色底 + 语义色 1px 描边」；若必须用彩色字，需选 700 深度的语义色并加大字号到 ≥13px。
**依据**：WCAG SC 1.4.3（正文 4.5:1）。
**优先级**：P2

### 8. 全站 12px 次要文案对比度 3.55–3.71，且存在 10.5px 低于 12px 下限
**证据**：`rgb(129,133,140)` 配白底实测 **3.55–3.71**，命中「共 5 条」「11 个子代理」「18 天」「引用 8 文件」等大量次要文案；雷达卡下「悬停维度查看解读」实测 **10.5px**（上一轮 #15 已明确"辅助文案不得 < 12px"）。
**修复建议**：次要灰提到 `#5F6673` 级别（≈4.6:1）；10.5px 提到 12px。
**优先级**：P2

### 9. 引用分析同一列表内混用三种截断策略
**证据**：`v0917b-agents-skill.png` + DOM 实测（括号内为 `title` 全文）：
`timer-app/index.html`、`react-vs-vue-report.md`（完整）/ `todo-app/research-rep…`（留头，扩展名被截掉）/ `…/hooks/useTodos.ts`（留尾）/ `…/unit/useTodos.test.ts`（去掉中段）。
**问题**：同一份 8 行列表里三条截断规则并存，用户学不到规律；留头行丢掉扩展名后无法判断文件类型，且 `todo-app/research-rep…` 与 `todo-app/tests/README…` 这类前缀相同的行必须 hover 才分得清——正是上一轮 #6 想解决的现象。
**修复建议**：统一为「留尾 + 前导省略」一种规则（`…/hooks/useTodos.ts`），列宽固定、`title` 保留全文；或直接等宽字体 + 目录名收窄、文件名不截断。
**优先级**：P2

### 10. 时间线首行缺 R1 标号，且标题列与其余行错位 22px
**证据**：`v0917b-timeline.png`。R2–R21 行文本列起点实测恒为 `x=404`；首行（★ 原始任务）无「R1」标号，文本起点 `x=426`。首行既有独立的星标 + 徽章，又在 21 行的纵向节奏里单独偏右 22px。
**修复建议**：首行补 `R1` 标号并让其文本列对齐 404；或明确把首行降级为"会话标题行"（换一套更弱的样式，不与 R 行同列）。
**优先级**：P2

### 11. 柱图悬停反馈与触发点分离，缺单位，且与操作提示互斥
**证据**：`v0917b-bar-hover.png`。悬停第 7 根柱时，反馈文案出现在**卡头最右侧**（距该柱水平约 350px、垂直约 70px），内容为「R7 · 300,350 · 实际中怎么使用?」。
**问题**：① 反馈不锚定在指针附近，视线需长距离跳跃；② `300,350` 无单位（token？字符？）；③ 悬停时原本常驻的操作提示「点击柱 → 定位下方时间线」被替换掉，恰好把"下一步能做什么"藏了起来；④ 柱体本身只有 `opacity 0.85→1` + 1px 浅色描边，反馈极弱。
**修复建议**：改为跟随柱体的浮层（或柱顶标注），文案含单位「R7 · 300,350 tokens · 实际中怎么使用?」；操作提示常驻在标题下方不参与替换；悬停时给柱体加 2px 品牌色描边。
**优先级**：P2

### 12. 五对象命名未完全闭合：Token 卡叫「用户提示」，抽屉叫「用户输入」
**证据**：`coach.token.profile.user = '用户提示'`，而 `coach.context.drawer.user = '用户输入'` / `input.kind.prompt = '用户输入'`（`locales/zh-CN.ts:179/205/209`）。点图例「用户提示」打开的是标题为「用户输入」的抽屉。
**修复建议**：统一为「用户提示」，与 `be07cc8` 的五对象对齐目标保持一致。
**优先级**：P2

## 六、结论与建议顺序

本轮在合并卡落地之上新发现 **P1 ×3、P2 ×9，无新增 P0**。最影响"一眼读懂"的是 **图例色点缺格（#1）** 与 **category/status 色混用（#2）**——两者叠加会让"输入构成"这张图基本读不通；最影响"点了会怎样"的是 **图例同貌异行（#3）**。建议顺序：

1. **P1 三条**（补色点 → 类别色与状态色分家 → 图例行为统一）：改完"输入构成"这张卡才算可信可用；
2. **P2 中的无障碍四连**（#5 焦点管理、#6 焦点环 + Tab 位、#7 徽章对比度、#8 次要灰对比度）：一起过一遍，避免二次返工；
3. **P2 打磨四条**（#4 抽屉气泡层级、#9 截断统一、#10 首行列对齐、#11 柱图悬停反馈）；
4. **命名收口**（#12）与人工补测项随发布前质检一起过。

截图证据全部落 `docs/verification/v0917b-*.png`（10 张）；本轮仅评审，未改动任何代码。
