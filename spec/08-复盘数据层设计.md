# dsh-coach 复盘数据层设计 v0.2a

> 定位：dsh-coach（会话复盘教练）的数据层——把「每次交互好不好」变成可计算、
> 可解释、可测试的指标与质量分。UI（复盘报告展示、建议生成）在 v0.2b/v0.2c 承接。
>
> 基线：dsh-coach（源自 dsh-context 改名，v1.1 三栏聚合）+ 竞品调研结论
> （「逐次交互质量评估」全行业空白；Token/用量统计是红海，本层只做质量分伴生指标）。

## 1. 范围与边界

- **做**：基于会话事件流（`readSession`）与谱系（`traceSession`）的确定性指标计算，
  覆盖 规模 / 交互质量信号 / 产物健康 / 质量分 v1；独立 `/coach/api` 只读端点。
- **明确不做 / 已停用**：
  - **`/ctx/api` 停用**：dsh-coach 不再注册该前缀（与 dsh-context-plugin 并存会
    webserver 重复路由冲突）；继承自 dsh-context 的「上下文」Tab 一并摘除——
    v0.2a 是纯数据层版本，页面无 UI 变化。
  - 逐交互明细时间线（v0.2b UI 承接，需要时再定义契约，避免返工）；
  - 改进建议生成（v0.2c，规则引擎）；
  - Token 口径的独立看板（伴生指标；官方 token-meter 投影在 v0.2b 接入）。

## 2. 设计原则

1. **确定性**：全部指标只依赖事件流可观测事实，不用 LLM，单测可精确断言。
2. **可解释**：每个维度一条独立规则、权重单源（`score.ts`），分数能解释成因。
3. **中性偏上**：无法评估时给中性分（如无文件产物 70），避免「无数据 = 低分」误判。
4. **与聚合器同口径**：callId 双源（顶层 / `message.source.callId`）、
   `isError`/`error` 失败判定、`meta.diffs` 产物分类、路径相对化，均与 `aggregator.ts` 一致。
5. **无跨请求状态**：每次请求即时计算（与 `/ctx/api` 同约定）。

## 3. 契约（`src/shared/types.ts` 单源）

```ts
export type CoachApiErrorCode =
  | 'COACH_SESSION_NOT_FOUND' | 'COACH_BAD_REQUEST' | 'COACH_INTERNAL'

export interface CoachScope {
  turns: number            // 出现事件的轮次数（去重）
  userTurns: number        // source.kind === 'user' 的消息数（主会话视角）
  assistantSteps: number   // assistant/message 事件数
  toolCalls: number        // 配对成功的工具调用数
  failedToolCalls: number  // 失败的工具结果数
  delegations: number      // 直接子会话数（traceSession 第一层）
}

export interface CoachSignals {
  followUps: number        // 追问 = max(0, userTurns - 1)
  interventions: number    // 人工干预：用户消息前的最后一个实质事件是 tool/result
  correctionTurns: number  // 纠错：干预中其前的 tool/result 是失败的
  repeatedReadFiles: number // 同文件 read ≥ 2 次的文件数（v1 不比内容）
  retriedFailures: number  // 同一轮次内同工具名失败 ≥ 2 次的分组数
  compactions: number      // compaction/start 事件数
}

export interface CoachArtifacts {
  writtenFiles: number     // 写入/编辑过的文件数（去重）
  createdFiles: number     // 最终操作态为 create 的文件数
  updatedFiles: number     // 被修改 ≥ 2 次的文件数（迭代信号）
}

export type CoachDimensionId = 'completion' | 'efficiency' | 'recovery' | 'artifact' | 'delegation' | 'context'
export interface CoachScore { total: number; dimensions: Array<{ id: CoachDimensionId; score: number }> }

export interface CoachReport {
  sessionId: string
  generatedAt: number
  scope: CoachScope
  signals: CoachSignals
  artifacts: CoachArtifacts
  score: CoachScore
}
```

## 4. 指标口径（判定规则）

| 指标 | 判定规则 | 备注 |
| --- | --- | --- |
| userTurns | `source.kind === 'user'` 的 `user/message` 计数 | plugin/team-message 不计 |
| followUps | `max(0, userTurns - 1)` | v1 简化：首个用户消息=初始任务，其后均算追问 |
| interventions | 用户消息前的**最后一个实质事件**是 `tool/result` | 实质事件=user/assistant/tool-call/tool-result；`turn/start` 等结构性事件不打断 |
| correctionTurns | 干预中其前的 `tool/result` 失败（`isError` 或顶层 `error`） | |
| repeatedReadFiles | 同一规范化路径被 `read` 成功 ≥ 2 次 | v1 不比对内容（v1.1 加指纹） |
| retriedFailures | 同一 `(turn, 工具名)` 分组失败 ≥ 2 次的分组数 | 跨轮次不算同组 |
| compactions | `compaction/start` 事件数 | 其他 compaction/* 不计 |
| 产物分类 | write（diffs 空=create）/ edit（update）/ str_replace_editor | 失败的 tool/result 不计入参考与产物 |

## 5. 质量分 v1（六维加权，权重单源在 `score.ts`）

| 维度 | 权重 | 判据 |
| --- | --- | --- |
| completion | 0.25 | 有非空最终答复 90；被中断 60；无答复 30 |
| efficiency | 0.20 | 无效占比 =（重复读+失败+重试）/ 总调用；无调用 100 |
| recovery | 0.20 | 成本 = 追问+干预+纠错×2，每单位扣 12（下限 0） |
| artifact | 0.15 | 有产物且迭代打磨 95；有产物未迭代 75；无产物 70 |
| delegation | 0.10 | 0 子会话 100；1-4 合理 90；5-8 偏多 70；>8 过多 40 |
| context | 0.10 | 无压缩 100；1 次 80；2 次 65；≥3 次 45 |

总分 = 加权和（四舍五入）。全部规则确定性、单测断言精确值。

## 6. API 契约

host 只暴露 `/coach/api` 一个前缀（v0.2a 起不再注册 `/ctx/api`）：

```
GET /coach/api/session/:id/report
  → 200 { ok: true, data: CoachReport }
  → 404 { ok: false, error: { code: 'COACH_SESSION_NOT_FOUND' } }
  → 400 { ok: false, error: { code: 'COACH_BAD_REQUEST' } }（非 GET / 未知路由）
  → 500 { ok: false, error: { code: 'COACH_INTERNAL' } }
```

- 前缀注册：`ctx.webServer.register({ kind: 'prefix', path: '/coach/api' })`；
- `dispatchCoachApi` 是纯分发函数（可脱离 node:http 做契约测试）；
- 会话不可得（readSession 数据层失败）→ `COACH_SESSION_NOT_FOUND`；
  实现缺陷（TypeError 家族）→ 上抛收敛为 `COACH_INTERNAL`（与 `/ctx/api` §7.3 同约定）。

## 7. 验证

- `tests/coach.spec.ts`：fixture 事件流逐指标精确断言（规模/追问/干预/纠错/无效动作/产物/压缩/六维分/路由分发）。
- `tests/coach.verify.spec.ts`：真实 V3 日志（fs-delete-recreate / text-turn / inline-image-prompt）对拍：
  确定性（两次扫描逐字段相等）、数值健康（有限/非负/不越界）、质量分 0-100。
