# DeepSeek Harness「上下文Tab」插件设计方案（v3 定稿 · 已确认）

> 2026-08-29 · 设计决策经用户确认，进入实施
> v2 修订：全部能力基于 DeepSeek Harness 基座自身，不与 dsh-workbench-plugin 耦合（不依赖其代码、事件族与 API；该插件仅作「机制可行」的佐证，工程结构/插件清单格式可作惯例参考）。

## 一、需求回顾

在主对话页面新增「上下文」Tab（放最右），同屏展示整个会话的三段内容：

- **输入**：用户提示词 + 随附的附件/文档，按时间排列；系统自动注入的上下文也归输入段，文件类注入同样以文件树展示，并与用户主动提供的内容明确区分；
- **参考**：会话过程中 Agent 查看过的文件，目录树排布，每个文件标注查看次数（重复读取累计计入——查看次数越多说明越重要），点击经抽屉查看正文；
- **输出**：文字输出（最终答复段落）+ 文件输出（产物清单，目录树排布，点击经抽屉查看正文）；
- 多 Agent 场景下，每条输入/参考/输出标注归属的 Agent。

## 二、已确认的设计决策

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 布局 | 方案 A：输入｜参考｜输出 三栏同屏（比例约 1 : 1.2 : 1） |
| 2 | Tab 排位 | 最右（order 取高值 100，排在对话 0 / 轨迹 10 / 任务 20 之后） |
| 3 | 查看次数口径 | 同会话重复读取累计计入 |
| 4 | 注入上下文 | 归输入段；文件类注入以文件树展示；区分「用户主动提供」（`source.kind='user'` 的提示词与附件）与「系统自动注入」（`source.kind='plugin'`，带 form/summary 语义标记） |
| 5 | 插件名 / API 前缀 | `dsh-coach`；API 前缀为插件内部路由命名空间（基座 `webServer.register` 单前缀路由），与其他插件/基座互不干扰 |

## 三、调研结论（代码库实测，全部基于基座能力）

### 3.1 Tab 注入：基座一等扩展点，无需改核心代码

- 主对话页 Tab 体系建立在 `conversation.view` list-slot 之上（`packages/client/ui-conversation/src/client/contract/slots.ts:116`），内置「对话」(order 0)、「轨迹」(order 10) 均以同一 API 注册（`ui-trajectory/src/client/index.ts:77-88`）——外部插件与内置包走完全相同的注册通道，无特权差异。
- Tab 栏生成、选中态持久化、locale、按会话注入数据、卸载清理全部由基座框架承担；官方 Slot 目录（`packages/extensions/cordis-client-runner/src/client/slot-catalog.ts:1291` 起）给出 `conversation.view` 的现成注册示例。
- 插件以「双面插件」交付：host（Node ESM）+ client（浏览器 factory bundle），经插件清单（`dsh.bundle.patch` + `dsh.client`）注册，`dsh plugin add` 即生效；client 端可声明注入基座包（如 `dsh-client-locale`）复用基座设计体系。

### 3.2 数据获取：三段数据均可从基座会话事件流提取

会话以 JSONL 事件流持久化（每会话一个 `session.jsonl`，`packages/session/session-persistence-jsonl/`），查询走基座 `SessionQueryEngine`（`packages/session-query/session-query/`：`readSession` / `filterEvents` / `traceSession` / `filterSessions({kind:'parent'})`）。

| 段 | 数据源（均为基座事件） | 说明 |
|---|---|---|
| 输入·用户主动 | `user/message` 且 `source.kind='user'`：提示词正文 + content 中 attachment 块（附件文档） | 时间线卡片 |
| 输入·系统注入 | `user/message` 且 `source.kind='plugin'`：带 `ContextForm`（instructions/catalog/snapshot/notice/relay/recall）与 summary | 文件类注入（如 AGENTS.md、skill 文档、文件变更通知中的文件）提取路径后并入注入文件树；其余按语义小类折叠 |
| 参考 | `tool/call` 中 `name ∈ {read, read_image}`（参数含 `file_path`）+ `str_replace_editor` 的 `command:'view'`；`tool/result.meta.path` 为基座持久化展示载荷 | 分组计数得查看次数 |
| 输出·文字 | `assistant/message` 事件（content 中 text 块） | 自实现逐轮提取纯函数 |
| 输出·文件 | `tool/call` 中 `write`/`edit`/`str_replace_editor(create/str_replace/insert)` + `tool/result.meta.diffs[].path` | meta 区分新建/更新 |

### 3.3 多 Agent 标识：基于基座 subagent 机制

1. 子 Agent 是独立会话：会话头携带 `parentSession / origin:'subagent' / delegationDepth / agentPreset`，其日志内事件整体归属该子 Agent；
2. 父会话 `subagent` 工具 `tool/result` 结构化输出携带子会话 `runId`/`subagentId` 回链；
3. 子会话内 `subagent/descriptor` 事件（基座事件）携带 `label / mode / provider`，作徽标显示名（缺省回落 `agentPreset`/会话 id 短码）；
4. 用基座 `traceSession` 与 `filterSessions({kind:'parent'})` 拉齐主会话与全部子会话日志后，每条记录的 Agent 归属完整可标注（会话级粒度）。

## 四、总体方案

### 4.1 插件形态

新建独立插件 `dsh-coach`（双面，目录 `dsh-coach/`）：

- **host 面**：经基座 `SessionQueryEngine` 按会话即时聚合事件流（不落盘、无自有状态，天然支持历史会话回看），暴露 `/ctx/api` 只读端点；
- **client 面**：注册 `conversation.view` 条目 `id:'context'`、`order:100`（最右）；UI 组件全部自建；
- 安装：`dsh plugin add` 即生效，不改基座一行代码，不依赖其他插件。

### 4.2 API 设计（GET 只读，前缀仅插件内部使用）

| 端点 | 用途 |
|---|---|
| `GET /ctx/api/session/<sessionId>/context` | 一次返回三段聚合结果：输入（用户主动条目 + 系统注入文件树/摘要，均含 Agent 归属）、参考树（查看计数、Agent 归属）、输出（文字段落摘要 + 文件树、新建/更新标记） |
| `GET /ctx/api/session/<sessionId>/file?path=` | 按需拉取文件正文（安全校验链，512KB 截断） |
| `GET /ctx/api/session/<sessionId>/output-text?index=` | 按需拉取文字输出全文 |

载荷预算：列表只带路径/计数/摘要，正文全部按需拉取。

### 4.3 数据口径要点

- 查看次数按 `tool/result.meta.path`（或 `tool/call` 参数 `file_path`）分组累计；`read_image`、`str_replace_editor view` 计入；
- 文件输出：`write` 标「新建」、`edit` 标「更新」；同文件多次编辑合并取最终态；
- Agent 徽标：主会话标「主Agent」，子会话标 `subagent/descriptor.label`；多子 Agent 时提供「按 Agent 筛选」下拉。

## 五、页面布局（方案 A · 已确认）

三栏同屏 输入｜参考｜输出（1 : 1.2 : 1）：

- 左栏·输入：上部「用户输入」时间线卡片（时间 + 提示词摘要 + 附件标签 + Agent 徽标），下部「系统注入」折叠区（非文件注入按语义小类折叠；文件类注入以目录树展示并带「系统注入」徽标）；长文「查看全文」开抽屉；
- 中栏·参考：目录树（自建 ContextFileTree），文件行尾查看次数徽标 `×N`（累计计数）+ Agent 徽标，点击开抽屉；
- 右栏·输出：上部「文字输出」卡片（末轮答复摘要 + 查看全文，可展开历史轮次），下部「文件输出」目录树（新建/更新标记 + Agent 徽标），点击开抽屉；
- 各栏头部带计数；超大树默认折叠 1 层 + 栏内滚动；
- 抽屉：自建 ContextDrawer，右侧滑出（loading/error/ready 三态、Esc/遮罩关闭、全屏放大），正文按扩展名基础高亮，头部带路径 + Agent 徽标 + 查看次数。

## 六、实施计划

1. **架构设计**（架构师）：插件骨架（host+client 双面）、API 契约、聚合器数据结构、文件清单与任务分解；
2. **host 实现**（工程师）：基座事件聚合器（输入分类/参考计数/输出提取/跨会话 Agent 归属）+ `/ctx/api` 路由 + 安全校验链（仅相对路径 → 拒 `..` → restrictPath 限定工作区 → realpath 反 symlink 逃逸 → 仅文件 → 512KB 截断）；
3. **client 实现**（工程师）：Tab 注册（order 100）+ 三栏布局 + ContextFileTree（计数徽标）+ ContextDrawer + Agent 徽标 + 注入文件树；
4. **测试验证**（QA）：聚合器单测（真实 session.jsonl fixture）、API 安全链测试、UI 手工验证清单。

工程量评估：中等（约 12~18 个源文件），走标准 SOP。
