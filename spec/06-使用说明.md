# dsh-coach 使用说明

> 面向使用与维护者。安装机制与设计背景见「文档索引」。

## 一、它做什么

在 DeepSeek Harness 主对话页新增一个**「上下文」Tab**（位于会话头部最右，排在 Chat / Trajectory 之后），同屏三栏呈现整场会话的来龙去脉：

- **输入**（左栏）：按 Agent 分组。每个 Agent 一块（主 Agent 最前），块内汇总它收到的内容——用户提示词、系统自动注入的文档、以及它收到的委派指令。用户主动提供的与系统自动注入的**明确区分**（注入文件带「系统注入」徽标）。
- **参考**（中栏）：会话过程中被查看过的文件，以目录树呈现，每个文件标注**查看次数**（重复读取累计计入，看得多说明越重要）。点击文件在右侧抽屉查看正文。
- **输出**（右栏）：只给**最终产物**——每个 Agent 各取其最终答复，加上产出文件清单（标注新建/更新）。逐轮、逐步骤的中间过程默认不显示，需要时打开「显示过程输出」开关。

多 Agent 场景下，每条输入、参考、输出都标注来源 Agent，并可按 Agent 筛选。

## 二、安装

### 前置条件

- 基座仓库（deepseek-harness）可用，且 pnpm 在 PATH 上；
- 本插件已构建：`lib/index.js`、`lib/client.js`、`lib/types/**` 在位（本仓库已含构建产物）；
- 确定要装进哪个 profile（主对话页用的是 `web`）。

### 装进 profile

**在基座仓库根执行** `pnpm dsh ...`（基座 `package.json` 已定义该脚本，是官方原生入口）。

```bash
# 1) 本地目录 —— 开发自用：改代码后 rebuild 即生效，无需反复 add
pnpm dsh plugin --profile web add ../dsh-coach

# 2) tarball —— 最"交付态"
(cd ../dsh-coach && npm pack)                       # 产出 dsh-coach-0.1.0.tgz
pnpm dsh plugin --profile web add ../dsh-coach/dsh-coach-0.1.0.tgz

# 3) 包名 —— 插件发布到 registry 之后的最终用户用法（当前尚未发布）
pnpm dsh plugin --profile web add dsh-coach
```

机制要点：

- `dsh plugin` **没有自己的 `add` 子命令**——`add` / `remove` / `why` / `update` 都是原样转发给 pnpm，并在 **profile 目录**里执行。所以包装到 `$DSH_HOME/profiles/<profile>/node_modules`（默认 `~/.dsh/profiles/<profile>/node_modules`），既不是基座仓库根，也不是当前目录。
- 装完后 dsh 自动对账：本包 `package.json` 声明了 `dsh.bundle.patch`，于是被自动追加进 `dsh.profile.bundles`——**profile 配置从不需要手写**。
- 只有以 `.` / `..` 开头的相对路径会被按调用目录锚定为绝对路径，其余写法原样交给 pnpm。

> **兜底**：个别环境下 `pnpm dsh` 会连带触发基座根的 `postinstall`（lefthook 安装）而失败。此时改用等价的直接调用，即 `package.json` 里 `dsh` 脚本的原文：
> `node --import tsx/esm apps/cli/src/bin.ts <子命令...>`（在基座仓库根执行）。

## 三、启动与验证

```bash
pnpm dsh --profile web --dump-config | grep dsh-coach   # 只看配置，不启动
pnpm dsh web                                              # 启动主对话页
```

- 第一条应看到 `- id: dsh-coach` / `name: dsh-coach`，表明已进入 bundle 层。
- **添加或移除插件后必须重启 profile 才生效**（pnpm 只改磁盘，运行中的 profile 沿用启动时的 bundle 集合；`cordis.patch.yml` 的改动则是热重载）。

装好并重启后，打开会话，Tab 栏形如 **Chat / Trajectory / Context**（中文 locale 下为「上下文」）。

## 四、界面怎么用

| 位置 | 操作 |
|---|---|
| 输入栏 | 展开某个 Agent 分组看它收到的内容；点条目开抽屉看全文；「系统注入」徽标标出非用户主动提供的内容 |
| 参考栏 | 目录树上的 `×N` 是查看次数；点文件开抽屉看正文（正文按扩展名做基础高亮） |
| 输出栏 | 默认只显示各 Agent 的最终答复；打开「显示过程输出」开关可展开中间过程；点「查看全文」看该段完整文字 |
| 顶部 | 按 Agent 筛选下拉；筛选后三栏联动，截断提示也按筛选后的可见内容重算 |
| 抽屉 | 支持 Esc 关闭、点遮罩关闭、全屏放大 |

## 五、卸载与日常维护

```bash
pnpm dsh plugin --profile web remove dsh-coach   # 同时移除依赖与 bundle 层，需重启生效
```

改代码后的日常循环（本插件目录内）：

```bash
npx vitest run                 # 249 个用例
npx tsdown --no-clean          # 构建（若 pnpm bundle 的 clean 步骤受限，用此等价替代）
npx tsc -p tsconfig.types.json # 类型产物
```

然后在基座仓库根重启 `pnpm dsh web` 生效。

## 六、常见问题

- **界面显示英文**（"Context" 而非"上下文"）：取决于基座当前 locale。本插件中英文案齐备（`'tab.label': '上下文'` 等），切换到中文 locale 即显示中文，非缺陷。
- **装了却看不到 Tab**：先确认 `--dump-config` 里有 `dsh-coach`，再确认**已重启 profile**。
- **安装时报 `workspace:` 协议错误**：已在 `3540e02` 根治（`peerDependencies` 改为真实 semver）。若手上是更早的 tarball，临时把 `peerDependencies` 改成 `*` 再装；自检命令：
  `tar -xzOf <tarball> package/package.json | grep 'workspace:'`（无输出即已修）。
- **peer 缺失告警**：`pnpm peers check` 可能仍报 `@deepseek-ai/*` missing，这是报告口径问题——运行期这些依赖由 `$DSH_HOME/profiles/node_modules` 这个安装闭包解析，不影响使用。
- **本机删除保护**：某些环境下批量删除保护会拦截 `$HOME` 下的 `rm`，而 `dsh` 启动需要清理 `profiles/node_modules.lock`。验证环境可用 `--store-dir /tmp/...` 与隔离的 `DSH_HOME` 规避；遇孤儿锁用 `mv` 移走而非删除。
