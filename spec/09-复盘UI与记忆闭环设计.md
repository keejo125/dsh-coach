# dsh-coach 复盘 UI 与记忆闭环设计 v0.2b/v0.2c

> 定位：在 v0.2a 数据层（
>
> `/coach/api/session/:id/report`
>
> ，逐交互指标 + 质量分 v1）之上，
> 交付两阶段能力 ——
>
> **v0.2b 复盘 Tab UI**
>
> （把报告可视化、可追溯）与
> **v0.2c 记忆提炼**
>
> （从过程里沉淀知识 / 规则 / 偏好，经用户确认后告知模型，不做注入、不落盘）。
> 基线：spec/08 数据层契约 + 竞品调研（质量评估空白、Token 统计红海）+ 用户已拍板的设计决策。

## 1. 范围与边界

**v0.2b 做（复盘 Tab UI）**：



* conversation.view 槽位注册「复盘」Tab（id=`coach`），消费现有 `/coach/api`；

* 区块：总分卡（评级 + 一句话解读）、六维雷达（hover 维度解读，即六维明细的落点）、本场统计（全局汇总条）、交互时间线（逐轮可展开）、

  产物清单、**子智能体面板**、**引用分析**（高频 Top + 未使用引用）、

  **Token 分布**（基座 tokenMeter，可降级）、**上下文构成**（复用 Context 聚合口径）；

* 新增 `/coach/api/session/:id/timeline`：逐轮明细（用户输入摘要、工具调用序列、信号徽标），

  这是 v0.2b **唯一的契约增量端点**。

**v0.2c 做（记忆提炼，用户收敛版）**：



* report 扩展 `insights[]`：确定性信号 → 候选条目（知识 / 规则 / 偏好 + 来源证据 + 置信度），全规则不引 LLM；

* report 扩展 `memoryLandscape`：**只读检测**当前可承载记忆的载体（项目级 / 用户级 / 会话级），

  为每条候选附「建议落点」提示；

* 新增 `POST /coach/api/session/:id/memory`：采纳条目 → **把该知识作为一条 plugin 消息告诉当前模型**，

  由模型自主判断如何存放 / 应用。**不写文件、不做会话启动注入、不做规约机制**。

**明确不做（本版）**：



* `/ctx/api` 前缀与「上下文」Tab（沿用 v0.2a 停用决定，与 dsh-context-plugin 并存零冲突）；

* 规则文件落盘（`.dsh/coach/rules.md`）、会话启动自动注入规约（用户拍板：注入先不做）；

* 记忆条目的 LLM 精修措辞（v1 全确定性；样本积累后 v2 再评估）；

* Token 独立看板（只做质量分 / 提炼的伴生指标，不跟 dsh-usage 拼面板）。

## 2. 设计原则



1. **数据单源**：UI 全部区块只消费 `/coach/api` 响应，不跨请求组装状态；刷新即重算。

2. **分数可追溯**：每个维度分数旁直接显示判据文字（"为什么是这个分"），不只给数字。

3. **过程即故事**：时间线按轮呈现「用户输入 → 助手动作 → 质量信号」，可展开工具明细。

4. **对人低要求**：用户只做两类动作 —— 看复盘、点确认；建议类内容只保留 1 条行动提示。

5. **对模型是主角**：提炼出的记忆条目交给模型自行判断存放，插件不替模型做持久化决策。

6. **确定性优先**：提炼信号（重复纠错 / 追问 / 失败重试 / 未用引用 / Token 大头）全为可观测事实，

   条目措辞用模板化生成；无数据不给高置信。

7. **可降级**：tokenMeter 服务不可得 → Token 区块显示「未启用」，不伪造数字。

## 5. 记忆提炼（v0.2c）

### 5.1 信号 → 候选（确定性规则 v1，不引 LLM）



| 信号（可观测事实）                | 候选类型       | 模板示例                      |
| ------------------------ | ---------- | ------------------------- |
| 用户纠正措辞 / 框架（干预 + 纠错同轮出现） | preference | 「用户偏好：{主题} 用 {纠正后的措辞}」    |
| 同轮同工具失败 ≥2 次后改对          | rule       | 「规则：{动作} 前先执行 {前置校验}」     |
| 重复读到同一文档 ≥2 次            | knowledge  | 「知识：{路径} 是本项目 {领域} 的权威来源」 |
| 未使用引用 ≥1 次               | knowledge  | 「知识：{路径} 与当前任务无关，可不用读」    |
| 追问 ≥2 次围绕同一主题            | preference | 「用户习惯：{主题} 期望先给方案再动手」     |
| 工具结果占 Token 大头（>40%）     | rule       | 「规则：避免把文件全文塞入上下文，按需读取」    |

置信度 = 信号强度加权（出现次数 / 同轮共现），无数据给 0，不猜测。

### 5.2 载体检测 `memoryLandscape`（只读扫描）



* **项目级**：AGENTS.md / CLAUDE.md / `.dsh/`（preset、plugins）/ 规则类文档（docs/*convention* 等）；

* **用户级**：`~/.dsh/.agent-presets/`、`~/.dsh/settings.yaml`、`~/.claude/` 等；

* **会话级**：已有注入条目（`source.kind === 'plugin'`，即本场已喂给模型的规约 / 知识）。

输出 `found[]`（载体名 / 路径 / 类型）+ 匹配规则给 `suggestedTarget`：

项目有 AGENTS.md → 建议 AGENTS.md；有用户级预设 → 建议 `~/.dsh/.agent-presets`；

均无 → 「项目暂无规约载体，可告知模型自行判断存放」。

### 5.3 采纳动作（不落盘、不注入机制）

`POST /coach/api/session/:id/memory {insightId, action:'accept'|'ignore'|'edit', content?}`：



* `accept`：经插件消息通道向当前会话注入一条 plugin 消息

  （`[coach·已确认知识] 用户确认：{content}。请自行判断如何存放/应用`），

  **由模型自主决定**写入规约、记住偏好或仅本场遵守；

* `ignore`：仅本地标记（不持久化，本场不复现该候选）；

* `edit`：改写内容后按 accept 处理。

**实现期待验证**：插件→会话注入的具体 API（dsh-context 的注入区证明通道存在，

但消息类型与权限需在真实 host 接线时确认）；若基座不允许插件发消息给 agent，

退路为「写入会话上下文投影（仅影响该场后续回合）」。

## 6. 评分联动（不改变质量分 v1 权重）



* 记忆提炼作为**第 7 类增值信号**，只做计数（「本场提炼 N 条候选」），不计入六维权重；

* 引用分析 ↔ efficiency 判据；子智能体 ↔ delegation 判据；Token 分布 ↔ 建议规则触发 ——

  均为展示层联动，不改 `COACH_DIMENSION_WEIGHTS`。
